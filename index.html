THE VANTA PRINCIPLE

The LLM interprets reality. The server owns reality.

Deterministic where truth matters. Probabilistic where language matters.

WHY VANTA

Stop testing whether someone can find the answer.

Traditional assessments often reveal whether a contestant knows a particular technique. VANTA asks a harder question: can they discover what matters when nobody hands them the problem statement?

01
No obvious root cause

Contestants begin with symptoms, not a neatly packaged technical problem.

02
Information is distributed

Different agents know different slices of the same hidden world.

03
Investigation is part of the assessment

The questions contestants choose become part of the problem-solving process.

04
Solutions are not passwords

Multiple technically valid approaches can satisfy the same underlying system properties.

THE INVESTIGATION LOOP

One world. Many ways through it.

Every investigation begins with uncertainty. The contestant decides where to look, who to ask, what evidence matters, and when they know enough to propose a fix.

01 / SYMPTOM

Something is wrong.

A realistic scenario provides an observable problem without revealing the technical cause.

02 / INVESTIGATE

Ask questions.

Contestants talk to AI-controlled people with different roles, memories, and authorized knowledge.

03 / EVIDENCE

Build the picture.

Useful facts accumulate while conditional knowledge can unlock as prerequisite evidence is discovered.

04 / HYPOTHESIS

Explain the mechanism.

Contestants turn fragmented evidence into a coherent diagnosis of what is actually happening.

05 / EVALUATE

Propose the fix.

Hidden deterministic tests decide whether the proposed solution satisfies the required properties.

THE EVALUATOR

Properties, not passwords. Correctness without guesswork.

VANTA does not ask an LLM whether a solution "looks right." Free text can be parsed into structured claims, but the final decision is made by deterministic checks against the world's required properties.

SUBMITTED SOLUTION FREE TEXT
diagnosis:   "critical reads can observe   stale replica state"
fix:   "route critical reads to the   primary database"
SOLUTION ACCEPTED

The proposed solution satisfies all required validation conditions.

✓ establishes consistency requirement
✓ accepted mechanism belongs to valid set
✓ proposed fix satisfies invariant
✓ no forbidden mechanism introduced

WHAT MAKES IT DIFFERENT

Designed as an assessment system. Not an AI chatbot with a costume.

01

Server-owned truth

Ground truth lives inside the world engine rather than inside a model's prompt.

02

Scoped knowledge

Agents become controlled perspectives over the same world, with explicit information boundaries.

03

Multiple valid solutions

Evaluation checks whether a solution satisfies required properties instead of matching a magic sentence.

04

Independent evaluator

Contestants receive only ACCEPTED or REJECTED while authorized administrators can inspect validation detail.
